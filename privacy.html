1. Overview

This document outlines the privacy practices of the YouTube Shorts Automation Tool ("the application"). The application is an internal, personal-use automation tool operated solely by the developer (harishharish988@gmail.com). Its primary function is to programmatically generate and upload short-form video content to YouTube channels owned and operated by the developer.

This application is strictly intended for private deployment and internal workflow automation. It is not offered, distributed, or commercialized as a public Software-as-a-Service (SaaS) product.

2. Information We Access and Use (Google User Data)

  • YouTube Data API v3 Scope (https://www.googleapis.com/auth/youtube.upload): Used strictly to authenticate with the developer's authorized YouTube channels to upload video files and set corresponding video metadata (titles, descriptions, tags, category IDs, and privacy status).
  • Basic Channel Metadata: Read-only access to basic channel identification details necessary to verify target channel upload destinations.
  • OAuth 2.0 Credentials & Access Tokens: Granted access and refresh tokens are stored locally and securely within restricted execution environments (such as private Google Drive storage or secure Google Colab runtime instances) solely to maintain authenticated API sessions for scheduled batch processing.

3. How Data Is Used, Stored, and Protected

  • Exclusive Internal Usage: All accessed data and API capabilities are utilized exclusively for executing automated video uploads to the developer's owned YouTube channels.
  • No Commercial Exploitation or Sharing: No Google user data, channel details, or authentication credentials are ever sold, rented, leased, or shared with third parties.
  • No Advertising or Profiling: Collected authentication data is never used for targeting advertisements, market research, user profiling, or surveillance.
  • No Machine Learning/AI Model Training: Google user data accessed via this application is strictly excluded from being used to train, tune, or fine-tune artificial intelligence or machine learning models.
  • Security & Storage Controls: OAuth client secrets, refresh tokens, and access tokens are secured using strict file-level access permissions and kept in private storage.

4. Data Retention and Deletion

Data Type Retention Period Deletion Mechanism
OAuth 2.0 Access & Refresh Tokens Retained only while automated publishing workflows remain active. Manual deletion of token credentials from the private runtime environment.
Video Files & Metadata Logs Retained temporarily in private execution storage during processing. Automatically purged from temporary runtime environments following successful API execution.

Access permissions granted to the application can be managed or permanently revoked at any time via the Google Account Security Permissions portal. Revoking access or deleting the stored token files immediately terminates the application's access to all Google services and data.

5. Google API Services User Data Policy Compliance

This application's use and transfer to any other app of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
